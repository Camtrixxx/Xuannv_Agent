# 开发计划 — 自定义地物「标注 / 训练」交接与恢复能力

> 目标：当用户请求的分析对象**不是服务原生地物**时，Agent 能识别出来、判断是否已有可用的自定义模型；若没有，则引导用户到外部标注页完成标注/训练，并在完成后**校验就绪、无缝恢复**原任务。Agent 只做「能力判定 + 交接 + 恢复」编排，**不做标注、不做训练、不做前端页面**（前端由他人实现，本仓库只提供 Agent 服务；调试期用 mock 跳转）。

## 1. 背景与关键事实

分析对象共 18 类，其中 7 类原生直接可用、3 类半原生（水体只能识别有无、不分河湖塘）、8 类需自定义标注（湿地、路口、操场、机场、体育场、垃圾场、火车站、露天停车场）。详见 `基于 10m 遥感数据底座的场景能力边界与应用方向.md`。

自定义训练走 embedding-api（`docs/API.md` @ go-bananas-wwj/embedding-api）：

- **训练**：`POST /models`（异步）→ 返回 `status:"training"` + `job_id`。请求体关键字段：`name`、`model_type`(`single_time_detection`/`change_detection`)、`region_id`、`embedding_version`(海淀=`v1`)、`annotations`(GeoJSON FeatureCollection, WGS84)、`classes`(每类 `id/name/color`)、`class_ids`(二值 few-shot 只允许 1 个)。
- **策略自动选择**：有效 Polygon **< 10 → `PU + Query` 向量检索（相似度召回）**；**≥ 10 → `binary_conv3x3` few-shot 卷积头**。✅ 阈值**已核实为 10**（embedding-api `docs/API.md`），同事口述的 5 不准。对 Agent 无影响：请求/推理接口完全一致，且 Agent 话术是阈值无关的（“少量样本即可，样本很少时系统自动用相似度召回”），无需硬编码这个数。
- **查状态**：`GET /models/jobs/{job_id}` → `status:running/completed/failed`。
- **列模型**：`GET /models?region_id=haidian` → 数组，含 `id/name/type/task_type/status/classes/source(custom|system)`。**已实测可用、无需鉴权**（默认 default 用户）。这是本功能的 linchpin。
- **推理**：`POST /models/{model_id}/infer`（体：`region_id/patch_id/month` 或 `before_month/after_month`）→ `{"result_url": "..."}`；结果 PNG 128×128，与系统专题结果同形状 → **可直接接入现有分析管线**。批量 `infer_batch`（≤100 patch）。

## 2. 设计总览：一道「能力判定门」

在真正 `run_analysis` 之前插入判定，结果四选一：

| 判定 | 依据 | Agent 动作 |
|------|------|-----------|
| 原生 | 目标 ∈ 系统任务/土地覆盖 7 类 | 走现有管线，不变 |
| 自定义·已就绪 | `GET /models` 有该类且 `status∈{completed,ready}` | 拿 `model_id`，经 infer 接入管线 |
| 自定义·训练中 | 有该类但 `status=training/running` | `NEEDS_INPUT`：告知稍候 |
| 需标注 | 两者都没有 | `NEEDS_ANNOTATION`：给标注入口 + 暂停，记住原任务 |

恢复：下一轮用户说「标注好了 / 继续」→ **查 API 真实状态**（不轻信用户）→ 就绪则用 `model_id` 恢复原任务；训练中则再等；失败则解释并可重来。

## 3. 已确认的三项决策

1. **恢复触发 = 用户手动 +Agent 校验**：用户回来说「好了/继续」，Agent 调 `GET /models/jobs/{job_id}`（或 `GET /models` 按类名匹配）确认 `completed` 才继续；不做定时轮询。
2. **自定义变化检测走「B 方案」**：优先训练 `single_time_detection` 模型 → 出两期掩膜 → **复用现有场景 B 像素级 diff 流水线**，让自定义类与原生类走同一条 diff+统计+报告链路（一致性最好）。`change_detection` 模型类型暂作为备选，不在首版接入。
3. **「目标物 → 类名」匹配 = 扩展 taxonomy + 动态并入自定义类**：
   - 在 `taxonomy.py` 增补一张「非原生对象别名 → 规范类名」表（湿地/机场/操场…及其口语说法）。
   - 运行时用 `GET /models` 发现的自定义类 `name` 动态并入，做别名/包含匹配，得到候选 `model_id`。

## 4. 分期实施

每期含：目标 / 改动文件 / 接口 / 测试 / 验收。全程 rules-first、不引入新依赖、纯函数优先、诚实标注局限。

### 阶段一：模型注册表服务（linchpin，纯真实 API 可测）
- **目标**：封装 `GET /models`，提供「某区域有哪些系统/自定义模型、某类是否已就绪、拿到 model_id」的查询。
- **新增** `agent/services/model_registry_service.py`：
  - `ModelRegistryService(config)`，内部用 `JsonHttpClient`。
  - `list_models(region_id) -> list[ModelInfo]`（短 TTL 缓存，默认 60s；含系统+自定义）。
  - `find_custom_models(region_id, class_name) -> list[ModelInfo]`：按 `classes[].name` 做规范化别名/包含匹配。
  - `model_status(model_id) / job_status(job_id)`：透传 `GET /models/{id}`、`GET /models/jobs/{job_id}`。
  - `ModelInfo` dataclass：`id/name/type/task_type/status/classes/source`，加 `is_ready` 属性（`status∈{completed,ready}`）。
- **新增** `agent/taxonomy.py`：`NATIVE_OBJECTS`（原生 7 类+水体的判定集合）、`NON_NATIVE_ALIASES`（湿地/机场/操场/体育场/垃圾场/火车站/露天停车场/路口 → 规范类名 + 口语别名）、`LAND_COVER_CLASSES`（土地覆盖 7 类中文名，供原生判定）。
- **测试** `tests/test_model_registry.py`：stub JsonHttpClient，验证列举/缓存/别名匹配/就绪判断；一个 `@live` 冒烟（可跳过）打真实 `GET /models`。
- **验收**：离线单测全绿；`GET /models?region_id=haidian` 能解析出实测里的 `水体/建筑/道路/变化区域` 等自定义类。

### 阶段二：能力判定 + 交接状态 + 记忆（纯 Agent 逻辑可测）
- **目标**：把「能力判定门」接进 `report_agent`，新增交接状态与 pending 记忆。
- **schemas/report.py**：
  - `AgentStatus` 增 `NEEDS_ANNOTATION = "needs_annotation"`。
  - `AgentResponse` 增 `action: dict`（交接指令：`type/url/class_name/model_type/params`），`to_dict` 已覆盖。
  - `AgentIntent` 增 `target_object: str`（本轮请求的分析对象，用于判定）与 `custom_model_id: str`。
- **新增** `agent/services/capability_service.py`：
  - `resolve(region, target_object) -> Capability`，返回 `kind ∈ {native, custom_ready, custom_training, needs_annotation}` + 可选 `model_id/job_id/status`。
  - 依赖 `taxonomy`（原生判定）+ `ModelRegistryService`（自定义判定）。
- **report_agent.py**：
  - `_detect_target_object`（从 prompt/taxonomy 抽取分析对象）。
  - 在 `_merge_memory` 各 scenario 分支**前**加 `_gate_capability`：非原生且未就绪 → 走交接/等待分支。
  - `_handoff_annotation`：构造 `action`（mock URL：`{frontend}/models/new?region_id=&class=&model_type=single_time_detection&month=`），status=`NEEDS_ANNOTATION`，把 `pending_custom_model`（目标类、原始 request 参数、可能的 job_id）写入 memory。
  - `_resume_after_training`：识别「好了/继续/训练完了」+ 存在 `pending_custom_model` → 查状态 → 就绪则填回 `custom_model_id` 并继续原 scenario；否则回稳态提示。
- **memory_service.py**：`pending_custom_model` 读写（get/set/clear）。
- **测试** `tests/test_capability_gate.py`：mock registry，四类判定 → 四种响应；恢复路径（training→completed）；「好了」在无 pending 时不误触发。
- **验收**：离线全绿；`请求湿地变化监测→needs_annotation+action.url`，`标注好了(mock completed)→继续出报告`。

### 阶段三：自定义模型接入分析管线（scenario B 优先端到端）
- **目标**：`custom_model_id` 就绪后，用 `POST /models/{id}/infer` 取结果 PNG，接入现有像素级 diff。
- **aoi_cover_service.py**：`fetch_result_array` 增 `model_id` 可选参数——有则走 `POST /models/{id}/infer`（拿 `result_url` 再取 PNG），无则走现有 `/system-models .../result`；两者返回同形状数组，diff 管线零改动。
- **change_monitor_service.py**：`analyze` 接受 `custom_model_id` 与自定义类名，掩膜阈值走「非背景即前景」通用规则（自定义二值输出目标/非目标）。
- **report_agent `_run_analysis`**：change 分支把 `custom_model_id` 透传给 service；method_notes/limitations 注明「基于自定义模型 model_xxx（少量样本相似度召回，精度参考）」。
- **测试** `tests/test_custom_change.py`：stub infer 返回两期数组，验证 diff 聚合与报告字段；`@live` 冒烟用实测里已就绪的自定义模型跑一次 infer。
- **验收**：`change` 场景可用自定义模型完成两期对比并出报告；诚实标注来源与精度局限。

### 阶段四：话术、边界与失败路径
- 训练中/失败/无匹配 patch/月份不可用 的友好文案；few-shot 阈值话术（「标注少量样本即可，系统自动相似度召回」）。
- 交接 `action` 契约文档化，供前端对接；调试 UI mock「新开标签页 + 完成确认」。
- 校验：不轻信「好了」，一律以 `job/model status` 为准；training 未完成时明确回「还在训练，请稍候再说『好了』」。

### 阶段五：文档与联调收尾
- 更新 `agent/API.md`（新增 `needs_annotation` 状态 + `action` 字段 + 自定义模型流程说明）、`CLAUDE.md`（新服务与判定门）、能力边界文档（标注入口）。
- 全量 pytest 全绿；live 4-way 冒烟 + 一条自定义类端到端；进度写入本文件「进度」节。

## 5. 风险与开放问题
- **few-shot 阈值 5 vs 10**：待 live 实测确认，仅影响话术。
- **前端交接契约**：`action` 字段结构需与真前端对齐；当前按 mock 约定，字段保持前向兼容。
- **自定义类名匹配歧义**：如「水体」既是原生又存在自定义模型——判定优先级需明确（原生优先，除非用户显式要自定义类如「湿地」）。
- **infer 时延**：逐 patch infer 可能慢；阶段三先串行+缓存，必要时用 `infer_batch`。
- **embedding_version**：海淀必须 `v1`，训练/推理都要带对，否则回退版本可能出错。

## 7. 联调记录（本地）

- 本地 embedding-api 实跑在 **`localhost:9061`**（非 8003；8003 无服务）。OpenAPI 路径与本仓库调用**完全一致**：`GET/POST /models`、`/models/jobs/{id}`、`/models/{id}`、`POST /models/{id}/infer`、`/regions/.../result`、`/system-models/.../classes`，Agent 代码无需改动，仅 `AGENT_EMBEDDING_API_BASE_URL` 指过去即可。`AGENT_ANNOTATION_UI_BASE` 默认与 embedding-api 同址（无硬编码前端端口）。
- 用真实 `CapabilityService`+registry 打 9061：本地 103 个模型（100 自定义），能力判定正确（湿地/机场→needs_annotation、建筑物→native），真实数据含 `failed` 状态模型，验证了 `custom_failed` 路径。
- ⚠️ **本地 9061 的 `infer` 暂不可用（后端数据问题，非 Agent 代码问题）**：多数已训练模型是 v2(128维) 权重，但本地 patch embedding 是 v1(64维)，后端推理张量不匹配（`expected 128 channels, got 64`）；个别换检模型缺对应月 embedding。远端 22065 上同一 `infer→PNG→掩膜` 链路可跑通。live infer 冒烟测试遇此环境条件时**优雅 skip**，不误报。需后端侧统一 embedding 版本后再做端到端 infer 联调。
