基于 10m 遥感数据底座的场景能力边界与应用方向
需要确认
（1）接入外部数据（POI、建筑物轮廓、道路、水系、居民点边界、规划审批等专题数据）
（2）不接入外部数据
接入外部数据会不会让别人质疑我们的能力，要强调我们目前的数据的限制
一、总体判断
我们当前的数据底座分辨率为 10m，也就是一个像元代表约 10m × 10m = 100 平方米 的地表范围。
因此，这套底座的核心价值不是“看清每一个单体设施”，而是 看懂一片区域的地表格局、生态状态、建设变化和风险趋势。
可以概括为一句话：10m 遥感底座适合做区域级、斑块级、趋势级和风险初筛级分析，不适合单体设施级精细识别。
它更适合回答：
- 这个区域水体、绿地、林地、裸地、硬化地表分别有多少？
- 近几年哪里发生了明显变化？
- 哪些区域生态压力较大？
- 哪些区域建设扰动明显？
- 哪些山前、水体周边、硬化高值区需要优先巡查或治理？
不适合直接回答：
- 哪栋楼是医院？
- 哪个建筑是学校？
- 哪个点是垃圾站？
- 单栋建筑边界在哪里？
- 哪个临建是违建？

1、不建议做的场景:
距离道路（改变道路：公路、铁路）500m（可更改）的某种基础设施（改变建筑物：医院、学校....)有哪些
（1）如果只是做“距离某设施距离多少范围内有多少什么设施”， ”距离道路 500 米内的某某建筑设施有哪些”这类问题，本质上是对象级 GIS 空间查询，需要明确知道哪些对象是医院、学校、垃圾站，以及道路、铁路的准确矢量位置。  传统 GIS 已经可以完成，不能体现我们的核心优势（因为数据也要使用外部的，这些工作就成为了传统的GIS分析工作）。 
这些问题属于 对象级识别和精细 GIS 分析，需要 POI、建筑物轮廓、道路、水系、居民点边界、规划审批等专题数据支撑，不能仅靠 10m 遥感影像独立完成。目前仅依靠 10m 遥感数据，我们可以识别建成区、硬化地表、大面积绿地、水体、裸地及其变化，但不能稳定识别单栋建筑的用途，也不能准确判断某栋建筑是医院还是学校。  
因此，在当前数据基础下，这类任务不宜作为主打场景。如果后续接入 POI、建筑物轮廓和道路矢量数据，则可以实现，并且可以叠加 10m 遥感底座提供周边环境和变化分析。”
我们的优势在于：可以以外部数据定义业务对象和分析范围，再利用 10m 遥感底座提供区域状态和多年变化，回答“这个范围内发生了什么变化、问题在哪里、风险是否升高、哪些区域需要优先治理”。  
因此，外部数据是辅助定位，遥感底座负责解释状态和变化，Agent 负责把问题拆解成可执行任务并生成结论。
（2）那即使接入外部路网、POI、建筑物数据，做以上任务的话，本质也主要是 传统 GIS 缓冲区分析（因为主要的数据基本上都是外部数据）。这类任务能做，但不太能体现 10m 遥感底座或 Alpha Earth 式数据底座的核心优势。
它体现的是：
- POI 数据能力
- 路网数据能力
- GIS 空间查询能力
而不是我们的：
- 多时相遥感变化能力
- 地表覆盖识别能力
- 统一格网底座能力
- 区域生态/建设状态表达能力
利用 10m 遥感底座提供区域状态和多年变化，回答“这个范围内发生了什么变化、问题在哪里、风险是否升高、哪些区域需要优先治理”。

2、分析底座可以做与不可以做的内容
（1）我们的底座适合做什么
基于 10m 遥感数据，我们可以稳定开展以下分析：
- 水体识别与面积变化
- 绿地、林地识别与变化监测
- 裸地识别与新增裸地监测
- 硬化地表识别与扩张监测
- 建成区扩张趋势分析
- 绿地/林地转硬化地表监测
- 山前带生态变化监测
- 河湖周边硬化压力分析
- 高硬化、低绿地区域识别
- 用户框选区域的综合生态体检
- 多年份生态空间变化报告
这些任务的共同特点是：
分析对象是成片地表类型，而不是单个设施或单栋建筑。
（2）我们的底座不适合做什么
仅依靠 10m 遥感数据，不建议把场景设计成以下类型：
- 医院、学校、垃圾站等具体设施识别
- 单栋建筑轮廓提取
- 小型屋顶识别
- 小型道路识别
- 临建、违建精确识别
- 小型垃圾站点识别
- 建筑用途判断
- 精确内涝模拟
- 真实热岛温度反演
原因是：
10m 像元尺度较粗，一个像元约 100 平方米。医院、学校、垃圾站等设施在影像中往往表现为屋顶、道路、树木、阴影、硬化地表等多种要素的混合，并不能仅凭 10m 光谱特征判断其具体用途。垃圾站等小型设施尺度更小，很多甚至不足一个像元。
因此，这类任务需要外部专题数据，例如 POI、建筑物矢量、设施台账、道路数据、规划审批数据等。
基于现有 10m 遥感数据底座，不建议把系统定位为“单体设施识别工具”，而应定位为“区域级生态与建设变化智能分析底座”。  
它适合识别和分析水体、绿地、林地、裸地、硬化地表等地表要素，适合开展多期变化检测、生态退化识别、建设扰动监测、山前生态敏感区筛查、水体周边缓冲带评估和生态修复优先区推荐。  
我们的优势在于：在不依赖大量人工解译和复杂数据准备的情况下，用户只要框选一个范围、提出一个问题，系统就可以快速生成地图、指标、变化清单和分析报告，为领导决策、巡查部署、项目谋划和资金申请提供依据。
因此，我们要重心放在：地表格局、生态状态、建设变化和风险趋势。（可以将外部路网、POI、建筑物数据结合，进行地表格局、生态状态、建设变化和风险趋势的分析，后续四五章节分别介绍接入数据，不接入数据。）
外部数据可以用，但不能让场景停留在 GIS 缓冲区查询；要让场景的核心答案来自 10m 底座的地表覆盖、变化检测和区域综合评价。

- 外部数据：设施 POI
- 底座能力：绿地率、硬化率、裸地、建设扰动变化
- 分析问题：设施周边环境质量是否变化

二、系统能带来的实际价值
1. 快速摸清现状
系统可以快速回答：
- 水体有多少？
- 绿地有多少？
- 林地有多少？
- 裸地在哪里？
- 硬化地表占比多高？
- 山前带生态状态如何？
价值：帮助领导快速掌握区域底数。
2. 快速发现变化
系统可以对比不同年份，发现：
- 哪些绿地减少？
- 哪些林地退化？
- 哪些地方新增硬化？
- 哪些裸地突然增加？
- 哪些水体发生变化？
价值：把“看不见的变化”变成地图和清单。
3. 快速形成问题线索
系统可以输出：
- 疑似建设扰动区
- 生态退化热点
- 高硬化低绿地区
- 水体周边扰动区
- 山前生态敏感区
- 生态修复候选区
价值：减少人工巡查范围，提高治理效率。
4. 支撑多场景复用
同一套 10m 底座可以支撑：
- 生态治理
- 防汛韧性
- 城市更新
- 山前生态安全
- 热岛缓解
- 生态修复
价值：不是一个项目建设一套数据，而是一套底座支撑多个治理场景。
5. 支撑 Agent 出题式分析
业务人员可以直接用自然语言提问：
- “这个片区生态状态怎么样？”
- “哪里建设扰动明显？”
- “哪些区域适合生态修复？”
- “河湖周边硬化压力在哪里？”
- “山前带有什么风险线索？”
系统自动完成：
范围识别 → 数据调用 → 指标计算 → 变化检测 → 结果解释 → 报告生成
价值：降低遥感分析门槛，让非专业人员也能使用。

三、数据限制
为了避免过度承诺，汇报时主动说明以下边界。
1. 不能独立识别医院、学校、垃圾站（小型，大型的很少）
原因：
10m 像元尺度较粗，且设施类型不是单靠光谱可以判断。医院、学校往往表现为建筑、道路、树木、操场等混合地表，垃圾站尺度更小，很多不足一个像元。
如要实现：
需要接入 POI、政务设施台账或建筑物矢量数据。
2. 不能识别单栋建筑边界
原因：
单栋建筑边缘会落在多个混合像元中，10m 影像边界不够精细。
如要实现：
需要亚米级影像、建筑物轮廓数据或倾斜摄影数据。
3. 不能做精确违建认定
原因：
违建认定需要权属、规划审批、建筑轮廓、现场核查等数据。遥感只能提供变化线索。
如要实现：
需要接入规划审批、用地红线、执法数据。
4. 不能做精确内涝模拟
原因：
内涝模拟需要 DEM、排水管网、降雨过程、下垫面参数和水文水动力模型。10m 遥感只能提供硬化率、绿地率、水体分布等基础因子。
如要实现：
可作为内涝模型的输入或初筛依据。
5. 不能做真实热岛温度反演
原因：
真实热岛温度需要热红外影像和气象数据。10m 地表覆盖数据只能做热岛风险代理分析。
如要实现：
需要接入热红外数据、气象数据和地表温度反演模型。
个人认为可以做综合性的复合型的任务作为场景，不是原来的单一任务，我们可以对该复合型的任务进行综合分析，解决好复合任务中的每个小任务，这样也目标明确，且综合任务的可理解性和可实用性强，便于管理者直接理解我们所做的事情可以解决哪些问题。（原来只是单一任务，与决策者之间有一定距离）
四、不接入外部数据，建议场景
基于现有 10m 遥感底座，建议将系统定位为：
区域级生态与建设变化智能分析底座。
重点建设以下 8 类复合型场景。

---
1、场景一：片区综合生态体检
场景边界
用户框选任意区域，系统对该区域内的地表覆盖结构和变化趋势进行综合分析。
不识别具体设施，不判断医院、学校、垃圾站等对象，只分析区域内：
- 水体
- 绿地
- 林地
- 裸地
- 硬化地表
- 多年变化趋势
- 生态压力分布
可实现任务
- 水体面积统计
- 绿地/林地面积统计
- 裸地面积统计
- 硬化地表比例统计
- 多年份变化趋势分析
- 高硬化低绿地区域识别
- 生态退化区域识别
- 片区生态体检报告生成
典型问题
- “帮我分析这个片区的生态空间现状。”
- “这个片区近五年绿地、裸地、硬化地表有什么变化？”
- “这个片区生态压力最大的位置在哪里？”
- “生成一份片区生态体检报告。”
为什么能做
水体、绿地、林地、裸地、硬化地表都是 10m 遥感数据能够较稳定表达的地表类型。尤其是做区域统计和多年趋势分析时，不依赖单个像元判断，而是依赖成片区域，可靠性更高。
能做到什么程度
可以做到：
- 片区级统计
- 斑块级识别
- 趋势级判断
- 问题区初筛
- 报告自动生成
不能做到：
- 单棵树识别
- 单栋建筑识别
- 具体设施用途判断
汇报价值
这个场景适合做领导快速掌握区域底数。
传统方式需要人工收集多期影像、预处理、分类、统计和制图；我们可以让用户框选区域后，系统自动输出“现状、变化、问题、建议”，支撑项目论证和日常治理。

2、场景二：蓝绿空间韧性评估（*）
场景边界
围绕水体、绿地、林地、硬化地表之间的关系，评估区域生态韧性、防汛韧性和宜居水平。
可实现任务
- 水体提取
- 绿地/林地提取
- 硬化地表识别
- 水体周边绿地缓冲分析
- 水体周边硬化压力分析
- 高硬化低绿地区域识别
- 蓝绿空间综合评分
典型问题
- “哪些区域蓝绿空间韧性较弱？”
- “水体周边 500 米内硬化地表比例是多少？”
- “哪些河湖周边绿地缓冲不足？”
- “哪些区域高硬化、低绿地，生态韧性较差？”
为什么能做
蓝绿韧性初筛，本质上是分析区域内：
- 水体是否充足
- 绿地是否连续
- 硬化地表是否过高
- 水体周边是否有足够生态缓冲
这些要素均可由 10m 遥感数据支撑。
能做到什么程度
可以做到：
- 区域蓝绿空间结构评价
- 水体周边缓冲带评价
- 高硬化低绿地区识别
- 韧性薄弱区初筛
不能做到：
- 精确内涝模拟
- 排水管网能力评估
- 具体建筑受淹判断
汇报价值
这个场景服务于防汛韧性、生态治理和城市更新。
我们不是替代专业水文模型，而是在没有完整管网和水文数据的情况下，先快速找出韧性薄弱区域，为现场排查和后续专业模型提供重点范围。

3、场景三：建设扰动与空间扩张监测（*）
场景边界
只分析片区级建设变化，不识别单栋建筑。
重点关注：
- 新增硬化地表
- 裸地增加
- 绿地转硬化
- 建成区扩张
- 疑似施工扰动斑块
可实现任务
- 建成区范围粗提取
- 硬化地表扩张检测
- 大面积裸地识别
- 裸地转硬化识别
- 绿地转建设/硬化识别
- 建设扰动强度评分
典型问题
- “近三年哪些区域建设扰动明显？”
- “哪些地方新增硬化地表？”
- “哪些区域从绿地变成了硬化地表？”
- “找出大面积裸地和疑似施工区域。”
为什么能做
建设活动通常会造成地表覆盖变化，例如：
- 绿地变裸地
- 裸地变硬化
- 非建成区变建成区
这种变化在 10m 多期遥感数据中可以通过对比识别出来。我们不是看清每栋楼，而是看“这片地表类型是否发生了变化”。
能做到什么程度
可以做到：
- 大斑块建设扰动发现
- 片区级扩张趋势判断
- 绿地转硬化线索识别
- 疑似施工区域初筛
不能做到：
- 小型临建识别
- 单栋建筑轮廓提取
- 违建执法认定
- 建筑用途判断
汇报价值
该场景适合城市更新、空间管控、存量空间盘活。
系统可以快速发现“哪里变了”，形成问题线索清单，大幅缩小人工巡查和现场核查范围。

4、场景四：生态空间退化监测（*）
场景边界
只关注生态空间变差的区域，不直接做责任认定或违法认定。
重点识别：
- 绿地减少
- 林地减少
- 裸地增加
- 水体减少
- 硬化扩张
- 生态空间转建设空间
可实现任务
- 绿地/林地变化检测
- 裸地增加检测
- 水体减少检测
- 绿地转裸地识别
- 绿地转硬化识别
- 生态退化热点识别
典型问题
- “近五年哪些区域生态退化明显？”
- “哪些区域林地减少并出现裸地增加？”
- “哪些区域绿地转为硬化地表？”
- “生成生态退化热点图。”
为什么能做
生态退化通常表现为地表覆盖类型转换，例如：
- 林地变裸地
- 绿地变硬化
- 水体缩小
- 裸地扩大
这些变化可以通过 10m 多期遥感分类结果进行识别。
能做到什么程度
可以做到：
- 退化线索识别
- 退化热点分布
- 转换路径分析
- 趋势报告
不能做到：
- 判断退化责任主体
- 判断违法占绿
- 完整评价生态系统健康状态
汇报价值
该场景服务生态监管、生态修复和山水林田治理。
它可以把“哪里可能在退化”提前发现出来，让治理从被动发现转向主动筛查。

5、场景五：山前生态安全敏感性评估
场景边界
适合山区、山前带、山水交界区，尤其适合研究区中山区占比较高的情况。
重点关注：
- 林地变化
- 裸地增加
- 硬化扩张
- 水体邻近
- 山前生态扰动
可实现任务
- 山地林地提取
- 林地减少识别
- 山区裸地增加识别
- 山前硬化扩张识别
- 山水交界扰动区识别
- 山前生态敏感区初筛
典型问题
- “山前带近五年哪里扰动明显？”
- “山区哪些地方林地减少、裸地增加？”
- “哪些硬化扩张靠近山体或水体？”
- “生成山前生态安全敏感区图。”
为什么能做
山区和山前带中，大面积林地、裸地、水体、硬化扩张都可以在 10m 数据中进行识别。山前生态安全关注的是大范围格局变化，而不是单个建筑。
能做到什么程度
可以做到：
- 山前生态扰动发现
- 敏感区初筛
- 巡查重点区识别
- 多期变化监测
不能做到：
- 精确滑坡预测
- 地质灾害专业判定
- 单个居民点安全结论
如果后续接入 DEM、坡度、历史灾害点等数据，可以进一步增强分析能力。
汇报价值
该场景体现了系统对山区研究区的适配能力。
我们可以把“山、水、城”的交界关系纳入统一底座，识别山前生态扰动和潜在敏感区域。

6、场景六：水体周边扰动与缓冲带评估
场景边界
只看水体周边一定距离内的地表覆盖和变化，不识别具体临水建筑。
可实现任务
- 水体边界提取
- 水体面积变化
- 水体周边绿地率统计
- 水体周边硬化率统计
- 水体周边裸地增加识别
- 水体周边缓冲带完整性评价
典型问题
- “水体周边 500 米内硬化率是多少？”
- “哪些水体周边绿地缓冲不足？”
- “哪些河湖周边出现裸地增加？”
- “近五年水体周边是否有硬化扩张？”
为什么能做
水体、绿地、硬化地表、裸地都是 10m 数据可以识别的对象。水体周边缓冲区分析，本质是对一定空间范围内的地表类型进行统计和变化检测，因此适合 10m 数据。
技术路径上也可以实现：
1. 从 10m 遥感数据中提取水体。
2. 将水体栅格转为矢量边界。
3. 按 100m、300m、500m 等距离生成缓冲区。
4. 在缓冲区内统计绿地、裸地、硬化地表及其变化。
5. 输出扰动等级和重点治理区。
能做到什么程度
可以做到：
- 河湖周边扰动识别
- 生态缓冲带评价
- 临水高硬化区域筛查
- 防汛韧性初筛
不能做到：
- 判断具体临水建筑
- 精确岸线工程结构识别
- 洪水淹没模拟
汇报价值
该场景服务河湖治理、防汛巡查和生态缓冲带修复。
系统可以快速识别“哪些水体周边压力较大”，为巡查和治理排序。

7、场景七：高硬化低绿地复合压力识别
场景边界
只用硬化地表、绿地、水体三个核心要素，识别生态压力和热岛风险潜在高值区。
可实现任务
- 硬化地表比例统计
- 绿地率统计
- 距水体或大块绿地距离分析
- 高硬化低绿地区识别
- 热岛风险辅助分区
- 补绿/透水化改造优先区识别
典型问题
- “哪些区域硬化率高、绿地率低？”
- “哪些区域可能热岛风险较高？”
- “哪些片区适合优先补绿？”
- “生成高硬化低绿地压力图。”
为什么能做
硬化地表和绿地在 10m 数据中可以较稳定表达。
虽然热岛风险需要热红外数据才能精确反演，但“高硬化、低绿地、远离水体”可以作为热环境压力的代理指标。
能做到什么程度
可以做到：
- 热岛风险辅助判断
- 生态压力分区
- 补绿优先区识别
- 硬化压力统计
不能做到：
- 实测温度反演
- 微气候模拟
- 建筑阴影和街谷风环境分析
汇报价值
该场景服务城市更新、花园城市、韧性城市和热岛治理。
它可以快速把“哪里需要补绿、哪里硬化压力大”用地图表达出来。

8、场景八：生态修复优先区识别（*）
场景边界
综合多个问题类型，筛选适合优先治理和修复的区域。
重点关注：
- 绿地减少
- 林地减少
- 裸地增加
- 水体周边硬化
- 高硬化低绿地
- 长期裸地
可实现任务
- 生态退化区识别
- 长期裸地识别
- 高硬化低绿地区识别
- 水体周边缓冲不足识别
- 修复优先级评分
- 修复候选区清单
典型问题
- “哪些区域最需要优先生态修复？”
- “找出绿地减少、裸地增加且靠近水体的区域。”
- “哪些高硬化区域适合补绿？”
- “生成生态修复优先区清单。”
为什么能做
该场景不是依赖单体设施识别，而是依赖多类地表覆盖问题的叠加。
10m 数据可以提供地表类型及其变化，因此适合用于修复优先区筛选。
能做到什么程度
可以做到：
- 修复候选区识别
- 优先级排序
- 问题类型说明
- 治理建议初稿
不能做到：
- 最终工程设计
- 土地权属判断
- 修复成本精算
- 施工方案制定
汇报价值
该场景直接面向决策。
它不仅告诉领导“哪里发生变化”，还进一步回答“哪里最应该优先治理”，适合用于项目储备、资金申请和治理清单编制。
是否接入外部数据，可根据是否将任务内容与基础设施或小尺度地物相关联，若想与基础设施或小尺度地物关联，可接入外部数据。
五、接入外部数据，建议场景
外部数据定义对象或范围，遥感底座提供状态和变化，Agent 输出问题线索和治理建议。
例如：
1、场景名：道路沿线建设扰动监测
- 外部数据：道路矢量
- 底座能力：硬化地表、裸地、绿地变化
- 分析问题：道路两侧是否发生建设扰动
- 输出结果：扰动路段、变化斑块、强度排名
典型问题：
“分析主干路两侧 500m 内近三年新增硬化和裸地变化，找出建设扰动最明显的路段。”
